# Environment

## Interpreter

`./.venv/bin/python` (3.14) is the interpreter that has Pillow and numpy. Use it for
every command; bare `python3` may not resolve the dependencies.

The toolkit is pure Python and needs no GPU, display or network. The drafts in `in/`
were produced with a ComfyUI checkout **outside** this repo — that is where image
generation happens, and nothing in `pixelkit/` depends on it.

## What is in git, and what is only on disk

Tracked inputs:

- `in/` — the twelve AI drafts the draft pipeline reads.
- `reference/mascot-witch.png` — the 83×122 native sprite the reference pipeline reads.
- `sprites/palette.json` — the frozen 61-colour palette. It decides every colour in
  the shipped set, so it is source, not build output; re-cutting it moves the whole set.
- `sprites/grids/*.txt` — the patched pose grids, the deliverable of that pipeline.

Ignored build output, regenerated by the commands in [README.md](../../README.md):

- `out/`, `examples/out/`.

Ignored side projects, present on disk but deliberately not tracked. Do not add them
back, and do not go looking for them in `git log`:

| Path | What it is |
|---|---|
| `article/` | the Habr write-up, its figures, and ComfyUI workflow dumps |
| `wallpaper/` | a Wallpaper Engine project built from the sprite |
| `work/` | Wallpaper Engine scratch: layer plates (`.npy`), crops, renders |
| `_research/` | a clone of the site the mascot is used on, plus a tarball |

## Gotchas

- Draft filenames are Cyrillic. Quote paths in shell commands.
- Driver output paths must land inside the repo — drivers call `.relative_to(ROOT)`.
  See [conventions](conventions.md).
- `out/witch_spec.json` is an `analyze` result, not a source file. `sprites/build.py`
  regenerates it when missing, so a fresh clone needs no setup step.
